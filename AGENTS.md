# Инструкции для агентов и разработчиков

Это демо-решение каталога МоегоСклада (Vendor API). Его читатели — вендоры и их кодовые
агенты: код отсюда берут за основу собственных решений, поэтому репозиторий оптимизирован
под копирование примеров, а не под переиспользование внутри себя.

## Как организованы примеры функционала

- Каждый крупный пример — **модуль** в своем каталоге со своим `README.md`
  (описанием модуля): назначение, карта файлов, платформенные особенности, чеклист адаптации.
- Общий код модуль трогает только в **помеченных местах**: строка или блок с комментарием
  `// [feature:<имя>]`. Никаких реестров фич, событийных шин и DI: подключение — явный
  `require_once` и вызов вроде `loyaltyOnInstall()`.
- Тесты — спецификация публичного контракта, не цель покрытия. На контракт и важный отказ хватает
  одного-двух тестов; новый тест нужен только там, где поведение не проверяет ни один существующий.
- Все тесты — в одном `tests/run.php` без фреймворка: PHP-процессы с встроенным сервером, mock внешних API
  (`tests/mock-api.php` отвечает за JSON API и Vendor API из очереди ответов), curl и SQLite. Группы тестов
  разделены комментариями: базовый контракт (жизненный цикл, user-context, лояльность), HTTP-клиент, сценарии и чаты.
  Тесты модуля помечены его меткой `[feature:<имя>]`.
- Дублировать мелкие утилиты внутри модуля можно; добавлять слои индирекции «на будущее» — нельзя.

## Навигация

- Задача **не** про Loyalty API → не открывайте `src/php/loyalty/**` и `frontend/src/loyalty/**`:
  базовое решение читается без них. То же для сценариев: `src/php/scenario/**`, `frontend/src/scenario/**`
  и `frontend/src/chat/**`.
- Нужно **взять модуль за основу** → прочитайте его `README.md` и найдите места, где он подключается к общему коду:
  `grep -rn "feature:loyalty" src/ frontend/src/`.
- Маршрут чтения базового решения: `src/php/api/vendor-endpoint.php` (жизненный цикл установки) →
  `src/php/lib/lib.php` (конфиг, `AppInstance`, HTTP-клиент, сессия) → `src/php/utils/update-settings.php` →
  `src/php/entry/iframe.inc.php` (данные страницы) → `frontend/src/iframe/IframePage.tsx` (вкладка «Основное»).

## Клиентский код

- Страница = PHP-оболочка в `src/php/entry/` + `page-data.ts` (тип данных, только типы) + React в `frontend/src/<страница>/`.
  Сервер — источник данных и авторизации, React — только представление; SPA-роутинга нет.
- UI только на `@moysklad/uikit`, импорты точечные: `@moysklad/uikit/components/<X>`. Собственный CSS —
  только `frontend/src/ui/theme.css`.
- Сборка фронта: `cd frontend && npm ci && npm run build` (в `src/php/assets/entry`, в git не хранится).

## Существующие модули

- `src/php/loyalty/` — программа лояльности: вкладка в основном iframe, `PUT .../loyalty`
  через Vendor API, заглушка провайдера Loyalty API. Описание: `src/php/loyalty/README.md`.
- `src/php/scenario/` — действия в сценариях МоегоСклада: блок `<scenario>` дескриптора, обработчик
  `POST .../scenario`, журнал срабатываний в окне чатов. Описание: `src/php/scenario/README.md`.
- `frontend/src/uikit-examples/` — вкладка «Примеры UI Kit»: секции-примеры компонентов кита,
  каждая — самодостаточный файл для копирования. Описание: `frontend/src/uikit-examples/README.md`.

## Команды

- `php tests/run.php` — тесты (PHP 8.2+ с curl, pdo_sqlite, sodium; зависимости через `composer install`),
  обязательно перед коммитом. Без локального PHP: `docker run --rm -v $PWD:/app -w /app php:8.2-cli php tests/run.php`.
- `php src/php/utils/generate-descriptor.php` — `descriptor.xml` в stdout.
- `docker compose up --build` — локальный запуск (нужен `.env`, см. `README.md`).
