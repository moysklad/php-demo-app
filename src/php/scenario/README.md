# Модуль «Действия в сценариях»

Пример точки встраивания, в которой у решения нет интерфейса: администратор аккаунта выбирает действие
решения в сценарии МоегоСклада, а при событии с документом МойСклад вызывает обработчик решения.

## Что демонстрирует

- Блок `<scenario>` дескриптора с действиями решения (`utils/descriptor.xml.php` берет список из `scenario.inc.php`).
- Обработчик `POST .../apps/{appId}/{accountId}/scenario` под service JWT с тремя вариантами ответа Vendor API.
- Журнал срабатываний в SQLite и его показ в окне чатов (`frontend/src/scenario/ScenarioJournal.tsx`).

## Платформенные особенности (важно)

- Действия доступны только у решений в статусе **Activated**: пока решение не настроено, в сценарии его не выбрать.
- `200` — действие выполнено, тело ответа не нужно. `400` с объектом `error` — отказ по вине пользователя,
  `errorMessage` попадает в историю выполнения сценария. `5xx` или ответ дольше **10 секунд** — МойСклад повторяет
  запрос по политике retry (каждые 5 минут в течение суток), поэтому долгие операции выполняйте асинхронно.
- `objectType` приходит именем сущности JSON API (`CustomerOrder`), в URL JSON API оно пишется строчными.
- Запросы МоегоСклада приходят без участия пользователя, поэтому результат виден только в собственном интерфейсе
  решения. Демо показывает журнал в окне чатов: оно доступно после активации всем пользователям аккаунта.

## Карта файлов

| Файл                                           | Роль                                                                                          |
|------------------------------------------------|-----------------------------------------------------------------------------------------------|
| `scenario.inc.php`                             | Список действий, модель события и SQLite-журнал (последние 50 на аккаунт), обработка действия: `log-event`, `fetch-object`, `reject`; данные журнала для фронта |
| `events.php`                                   | `POST scenario/events.php` — журнал для окна чатов (авторизация по `contextNonce`)             |
| `frontend/src/scenario/ScenarioJournal.tsx`    | Журнал: список действий, таблица срабатываний, подробности по клику                           |

## Где модуль подключается к общему коду

Все такие места помечены: `grep -rn "feature:scenario" src/ frontend/src/`.

- `src/php/utils/descriptor.xml.php` — блок `<scenario>` с действиями;
- `src/php/api/vendor-endpoint.php` — вызов `handleScenarioAction()` для `POST .../scenario`;
- `src/php/entry/iframe.inc.php` — `scenarioJournal()` в данных окна чатов (`buildChatPageData()`);
- `frontend/src/chat/page-data.ts` и `ChatPage.tsx` — поля журнала и рендер `ScenarioJournal`.

## Как проверить

1. Установите решение и настройте его, чтобы статус стал `Activated`.
2. На странице сценариев МоегоСклада создайте сценарий для Заказа покупателя с действием решения.
3. Измените заказ и откройте окно решения в разделе «Чаты»: в журнале появится срабатывание.
4. Для действия «Отклонить с сообщением пользователю» сообщение решения видно в истории выполнения сценария.
