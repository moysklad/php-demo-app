# Модуль «Программа лояльности» (Loyalty API)

Пример точки встраивания, которая подключается по желанию: решение подключает программу лояльности
к аккаунту МоегоСклада и выступает провайдером Loyalty API (Discount API).

## Что демонстрирует

- Вкладку «Программа лояльности» внутри основного iframe (у решения один основной iframe —
  разделы вендор организует внутри своей страницы сам).
- Передачу настроек (`url`, `token`, `externalSearch`) в МойСклад через
  `PUT /apps/{appId}/{accountId}/loyalty` Vendor API, с разбором ошибок и подсказками.
- Заглушку методов Loyalty API, которые вызывает МойСклад, включая внешний поиск покупателей.
- Хранение подключения и его жизненный цикл при Install/Suspend/Uninstall решения.

## Платформенные особенности (важно)

- `<loyaltyApi/>` в дескрипторе — только «пропуск» на `PUT .../loyalty`: без него Vendor API
  отвечает ошибкой `2006`. Сам по себе элемент ничего не включает и на каталог не влияет.
- **Первый успешный `PUT .../loyalty` может включить программу лояльности как активную
  скидочную систему аккаунта**, если других активных скидок на нем нет. На рабочем аккаунте
  это меняет поведение Точки продаж — подключайте демо на тестовом аккаунте.
- При **Uninstall** МойСклад удаляет настройки лояльности на своей стороне; при **Suspend** —
  только приостанавливает. Поэтому решение хранит признак `connected_at` и сбрасывает его
  при Install/Uninstall, сохраняя токен.
- В ответе внешнего поиска покупателей поля `id` и `msId` МойСклад разбирает как **UUID** —
  произвольные строки не пройдут.
- Подключение опционально: на статус решения (`SettingsRequired`/`Activated`) оно не влияет,
  у него собственный индикатор на вкладке.

## Карта файлов

| Файл                                     | Роль                                                                                          |
|------------------------------------------|-----------------------------------------------------------------------------------------------|
| `loyalty.inc.php`                        | Модель и SQLite-хранилище подключения (токен шифруется), состояние для вкладки, реакция на Install/Uninstall, клиент `PUT .../loyalty` с подсказками по ошибкам 2004/2006/2007, демо-покупатели |
| `provider.php`                           | Заглушка провайдера Loyalty API: методы, которые вызывает МойСклад, авторизация по токену      |
| `connect.php`                            | `POST loyalty/connect.php` — backend формы подключения (авторизация по `contextNonce`)          |
| `frontend/src/loyalty/LoyaltyTab.tsx`    | Вкладка: статус подключения, описание и переход к примерам реализации                         |
| `frontend/src/loyalty/AuthModal.tsx`     | Диалог «Войти / Зарегистрироваться» — демонстрация рекомендованного сценария                  |
| `frontend/src/loyalty/ManualModal.tsx`   | Диалог прямой передачи настроек: форма и отправка в `POST loyalty/connect.php`                |

## Методы провайдера

URL провайдера по умолчанию — `{APP_BASE_URL}/loyalty/provider.php`. МойСклад дописывает к нему путь метода,
он приходит в `provider.php` через `PATH_INFO`, поэтому `mod_rewrite` не нужен. Каждый запрос несет токен
подключения в заголовке `Lognex-Discount-API-Auth-Token`, без совпадения с сохраненным токеном — `401`.

| Метод                           | Ответ заглушки                                                       |
|---------------------------------|----------------------------------------------------------------------|
| `POST /counterparty`            | `201`                                                                |
| `GET /counterparty?search=`     | демо-покупатели; `404`, если `externalSearch` выключен               |
| `POST /counterparty/detail`     | нулевой бонусный баланс                                              |
| `POST /retaildemand/recalc`     | позиции без скидки, нулевые бонусы                                   |
| `POST /retaildemand`            | `201`                                                                |
| `POST /retailsalesreturn`       | `201`                                                                |

Ошибки отдаются в формате Loyalty API: `{"errors": [{"error", "code", "error_message"}]}`.

## Где модуль подключается к общему коду

Все такие места помечены: `grep -rn "feature:loyalty" src/ frontend/src/`.

- `src/php/utils/descriptor.xml.php` — `<loyaltyApi/>` в дескрипторе;
- `src/php/api/vendor-endpoint.php` — вызовы `loyaltyOnInstall()` и `loyaltyOnUninstall()`;
- `src/php/entry/iframe.inc.php` — `loyaltyIframePageData()` в данных страницы iframe;
- `frontend/src/iframe/page-data.ts` — поля `loyalty` и `defaultLoyaltyProviderUrl`;
- `frontend/src/iframe/IframePage.tsx` — `Tabs.Item` и рендер `LoyaltyTab`.

## Как взять модуль за основу

1. Скопируйте каталоги `src/php/loyalty/` и `frontend/src/loyalty/` в свое решение.
2. Добавьте подключения из списка выше (начните с `<loyaltyApi/>` в дескрипторе).
3. Замените заглушки в `provider.php` на бизнес-логику: хранение участников и балансов,
   правила скидок, начисление и списание бонусов, идемпотентность.
4. Реализуйте необязательные методы, если они нужны: `POST /counterparty/verify`
   (подтверждение регистрации кодом), `POST /retaildemand/verify` (подтверждение списания),
   `GET /giftcard` (подарочные сертификаты).

На что обратить внимание:

- Порядок при подключении: сначала решение сохраняет новый токен как ожидающий, потом
  отправляет его в МойСклад через `PUT .../loyalty`. Пока МойСклад не подтвердил настройки,
  провайдер принимает и действующий, и ожидающий токен. Если сохранять токен после `PUT`,
  при сбое сохранения МойСклад будет присылать токен, который решение не знает. Если сразу
  заменить действующий токен, неудачное переподключение сломает работающую кассу. В обоих
  случаях каждый запрос Loyalty API получит `401`.
- Отказ Vendor API (4xx) означает, что настройки не применились, — ожидающий токен удаляется.
  Таймаут или 5xx означают, что исход неизвестен, — ожидающий токен остается до следующего
  успешного подключения.
- Диалог «Войти / Зарегистрироваться» на вкладке — только демонстрация сценария. Во внешнюю
  программу лояльности он не обращается, а показывает, какие данные и каким запросом
  попадут в МойСклад.
